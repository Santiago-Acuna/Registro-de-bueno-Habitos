**As a** Backend Developer
**I want to** create a domain validator for global entity identifiers
**So that** validation logic is centralized, reusable, and follows DDD principles

## Acceptance Criteria

### Structure & Location
- [x] Create validator at `src/domain/validators/global-identifier.validator.ts`
- [x] Validator is a pure domain service with NO framework dependencies
- [x] Validator uses dependency injection for repository access
- [x] Create corresponding test file at `src/domain/validators/__tests__/global-identifier.validator.spec.ts`

### Core Validation Methods
The validator must provide two distinct validation strategies:

#### 1. validateForHabit(name: string, icon: string, habitId?: UUID)
- [x] Validates that name is globally unique across ALL habits
- [x] Validates that icon is globally unique across ALL habits
- [x] Uses IdentifierName.create() and IdentifierIcon.create() for value object validation
- [x] When habitId provided (update scenario), excludes current habit from uniqueness check
- [x] Throws ConflictError if name already exists globally with message: "Habit name '[name]' is already in use"
- [x] Throws ConflictError if icon already exists globally with message: "Habit icon '[icon]' is already in use"
- [x] Throws ValidationException for invalid format from value objects
- [x] Returns validated IdentifierName and IdentifierIcon objects

#### 2. validateForActionType(name: string, icon: string, habitId: UUID, actionTypeId?: UUID)
- [x] Validates that name is unique ONLY within the specified habit (per-habit uniqueness)
- [x] Validates that icon is unique ONLY within the specified habit
- [x] Uses IdentifierName.create() and IdentifierIcon.create() for value object validation
- [x] When actionTypeId provided (update scenario), excludes current action type from uniqueness check
- [x] Throws ConflictError if name exists for this habit with message: "ActionType name '[name]' already exists for this habit"
- [x] Throws ConflictError if icon exists for this habit with message: "ActionType icon '[icon]' already exists for this habit"
- [x] Throws ValidationException for invalid format from value objects
- [x] Requires habitId parameter (mandatory for action types)
- [x] Returns validated IdentifierName and IdentifierIcon objects

### Return Type

interface ValidatedIdentifiers {

### Error Handling
- [x] Map value object errors to ValidationException with clear messages

## Technical Notes

**DDD Compliance:**
- Validator belongs in domain layer as it contains business validation rules
- No dependencies on infrastructure (NestJS, Prisma, etc.)
- Pure TypeScript class that can be tested independently
- Repository interface defines contract, not implementation

**Design Pattern:**
- Strategy Pattern: Different validation strategies (global vs per-habit)
- Repository Pattern: Abstract data access through interface
- Value Object Pattern: Leverage existing IdentifierName and IdentifierIcon

**Testing Requirements:**
- Test both validation methods independently
- Test update scenarios (with exclusion)
- Test error cases (conflicts, invalid formats)
- Mock repository responses
- Verify correct error messages

## Example Usage

```typescript
// For Habit creation
const validator = new GlobalIdentifierValidator(repository);
const { name, icon } = await validator.validateForHabit(
  'Exercise Daily',
  'https://example.com/exercise.png'
);

// For ActionType creation
const { name, icon } = await validator.validateForActionType(
  'Morning Run',
  'https://example.com/run.png',
  habitId
);

// For Habit update
const { name, icon } = await validator.validateForHabit(
  'Exercise Daily',
  'https://example.com/exercise.png',
  existingHabitId // Exclude from uniqueness check
);
```
