### Provider Configurations

#### GlobalIdentifierValidator Provider
```typescript
{
  provide: GlobalIdentifierValidator,
  useFactory: (repo: IGlobalIdentifierValidationRepository) => {
    return new GlobalIdentifierValidator(repo);
  },
  inject: ['IGlobalIdentifierValidationRepository']
}
```

## Technical Notes

**Module Dependency Graph:**
```
AppModule
├── InfrastructureModule
│   ├── PrismaService
│   └── GlobalIdentifierValidationRepository -> IGlobalIdentifierValidationRepository
├── DomainModule (optional, can be @Global())
│   └── GlobalIdentifierValidator -> IGlobalIdentifierValidationRepository
├── HabitsModule
│   ├── imports: [InfrastructureModule, DomainModule]
│   ├── HabitsRepository -> PrismaService, GlobalIdentifierValidator
│   └── HabitsService -> IHabitsRepository
├── ActionTypesModule
│   ├── imports: [InfrastructureModule, DomainModule]
│   ├── ActionTypesRepository -> PrismaService, GlobalIdentifierValidator
│   └── ActionTypesService -> IActionTypesRepository
└── GlobalEntityIdentifiersModule
    ├── imports: [InfrastructureModule, DomainModule]
    └── GlobalEntityIdentifiersService -> IGlobalEntityIdentifiersRepository, GlobalIdentifierValidator
```

**Best Practices:**
1. Use string tokens for interface bindings: `'IGlobalIdentifierValidationRepository'`
2. Use class tokens for concrete classes: `GlobalIdentifierValidator`
3. Export providers from modules that other modules need to import
4. Keep domain module free of infrastructure dependencies
5. Use useFactory for complex provider initialization

**Potential Issues:**
- Watch for circular dependencies between modules
- Ensure PrismaService is available before repositories
- Verify validator is instantiated before repositories
- Check that all imports/exports are correct

**Testing Strategy:**
1. Unit test each provider configuration in isolation
2. Integration test module imports/exports
3. E2E test full request flow
4. Verify dependency injection container resolves all dependencies
