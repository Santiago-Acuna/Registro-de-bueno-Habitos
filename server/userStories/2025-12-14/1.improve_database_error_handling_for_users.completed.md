# US-001: Improve Database Error Handling for Non-Developer Users

**As a** Backend Developer
**I want to** improve error messages for database constraint violations
**So that** end users receive clear, actionable feedback when uniqueness constraints are violated

## Problem Statement

Currently, when a unique constraint is violated (e.g., duplicate name or icon), users receive a generic error message:
```json
{
  "error": "DatabaseError",
  "message": "A record with this unique field already exists",
  "statusCode": 409,
  "details": {
    "code": "P2002",
    "meta": { "target": ["name"] }
  }
}
```

**Problems:**
- ❌ Generic message doesn't specify which field (name or icon)
- ❌ User must dig into `details.meta` to understand the issue
- ❌ Not actionable for non-developer users

## Acceptance Criteria

### Enhanced P2002 Error Handling
- [ ] Parse `exception.meta.target` to extract the conflicting field name
- [ ] Return user-friendly messages that specify the exact field
- [ ] Handle multiple fields in constraint (e.g., composite unique constraints)
- [ ] Maintain 409 CONFLICT status code
- [ ] Keep technical details in `details` object for debugging

### Implementation Details

**Location:** `src/infrastructure/filters/http-exception.filter.ts`

**Method to modify:** `handlePrismaException()` - case 'P2002'

**Steps:**
1. Extract field names from `exception.meta?.target` array
2. Create a helper method `buildUniqueConstraintMessage(fields: string[])`
3. Generate user-friendly message based on field count:
   - 1 field: "The {field} is already in use. Please choose a different {field}."
   - 2+ fields: "A record with this {field1} and {field2} combination already exists."
4. Add extracted fields to details object for debugging
5. Handle edge cases (missing meta, empty target array)

- ✅ Better performance (no pre-validation queries)

## Example Implementation Snippet

```typescript
private handlePrismaException(
  exception: Prisma.PrismaClientKnownRequestError,
  request: Request
): ErrorResponse {
  let statusCode: HttpStatus;
  let message: string;

  switch (exception.code) {
    case 'P2002':
      statusCode = HttpStatus.CONFLICT;
      const fields = exception.meta?.target as string[] | undefined;
      message = this.buildUniqueConstraintMessage(fields);
      return {
        error: 'DatabaseError',
        message,
        statusCode,
        timestamp: new Date().toISOString(),
        path: request.url,
        details: {
          code: exception.code,
          meta: exception.meta,
          ...(fields && fields.length === 1 && { field: fields[0] }),
          ...(fields && fields.length > 1 && { fields }),
        },
      };
    // ... other cases
  }
}

private buildUniqueConstraintMessage(fields?: string[]): string {
  if (!fields || fields.length === 0) {
    return 'A record with this unique field already exists.';
  }

  if (fields.length === 1) {
    const field = fields[0];
    return `The ${field} is already in use. Please choose a different ${field}.`;
  }

  const fieldList = fields.join(' and ');
  return `A record with this ${fieldList} combination already exists.`;
}
```
