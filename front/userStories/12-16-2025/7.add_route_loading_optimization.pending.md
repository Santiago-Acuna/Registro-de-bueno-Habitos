# US-007: Add Route Configuration Caching and Refresh Strategy

**Priority:** Low
**Complexity:** Small
**Estimated Time:** 1.5 hours
**Dependencies:** US-005

## User Story

As a user, I want routes to load instantly on subsequent app visits so that I don't have to wait for route configuration every time I use the application.

## Description

Implement caching strategy for route configuration using localStorage to persist routes between sessions, with a smart refresh mechanism to keep routes up-to-date when backend configuration changes.

## Acceptance Criteria

**Given** routes have been fetched successfully
**When** the user closes and reopens the application
**Then** cached routes should load instantly from localStorage while fresh routes are fetched in the background

**Given** cached routes exist in localStorage
**When** the application loads
**Then** it should:
- Immediately render cached routes
- Fetch fresh routes in background
- Update routes if backend config has changed
- Show no loading state (use cached routes)

**Given** backend configuration has changed
**When** fresh routes are fetched
**Then** routes should update seamlessly without jarring UI changes

**Given** no cached routes exist
**When** the application loads for the first time
**Then** show loading state while fetching routes

## Technical Implementation

### Caching Strategy

```typescript
// Cache structure in localStorage
interface RouteCacheEntry {
  routes: RouteConfig[];
  timestamp: number;
  version: string; // API version
}

// Cache key
const ROUTES_CACHE_KEY = 'habit-tracker-routes-cache';
const CACHE_VERSION = 'v1';
```

### Cache Operations

```typescript
// Save routes to cache
function cacheRoutes(routes: RouteConfig[]) {
  const entry: RouteCacheEntry = {
    routes,
    timestamp: Date.now(),
    version: CACHE_VERSION,
  };
  localStorage.setItem(ROUTES_CACHE_KEY, JSON.stringify(entry));
}

// Load routes from cache
function loadCachedRoutes(): RouteConfig[] | null {
  const cached = localStorage.getItem(ROUTES_CACHE_KEY);
  if (!cached) return null;

  const entry: RouteCacheEntry = JSON.parse(cached);

  // Invalidate if version mismatch
  if (entry.version !== CACHE_VERSION) {
    localStorage.removeItem(ROUTES_CACHE_KEY);
    return null;
  }

  return entry.routes;
}
```

### Redux Slice Updates

```typescript
// Add cache-related actions
- setCachedRoutes(routes: RouteConfig[]) - Load from cache
- updateRoutesInBackground(routes: RouteConfig[]) - Background update
```

### Modified App Loading Flow

```typescript
useEffect(() => {
  // 1. Load cached routes immediately
  const cached = loadCachedRoutes();
  if (cached) {
    dispatch(setCachedRoutes(cached));
  }

  // 2. Fetch fresh routes in background
  fetchRoutes().then(freshRoutes => {
    // Cache fresh routes
    cacheRoutes(freshRoutes);
  });
}, []);
```

## Edge Cases

- localStorage full (quota exceeded)
- localStorage unavailable (private browsing)
- Corrupted cache data
- Version mismatch between cache and app
- Network error during background refresh
- Cache and fresh routes differ significantly
- User clears browser data

## Validation Rules

- Cache version must match current app version
- Cached routes must have valid structure
- Cache should not exceed reasonable size (< 1MB)
- Invalid cache should be cleared automatically
- Cache should be JSON-serializable

## Cache Strategy Details

### Cache Lifecycle

1. **Initial Load**
   - Check localStorage for cache
   - Load cached routes if valid
   - Show app immediately with cached routes
   - Fetch fresh routes in background

2. **Background Update**
   - Compare fresh routes with cached
   - Update if different
   - Save fresh routes to cache

3. **Cache Invalidation**
   - Version mismatch
   - Corrupted data
   - User action (logout, clear data)
   - Optional: Time-based expiration

### Performance Metrics

- **Without Cache**: 500-2000ms initial load time
- **With Cache**: < 100ms initial load time
- **Background Refresh**: Transparent to user
