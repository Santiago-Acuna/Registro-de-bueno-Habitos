# US-001: Create Redux Slice for Routes Configuration

**Priority:** High
**Complexity:** Medium
**Estimated Time:** 2 hours
**Dependencies:** None

## User Story

As a frontend developer, I want a Redux slice to manage route configuration state so that dynamic routes can be stored and accessed throughout the application.

## Description

Create a new Redux slice to store and manage route configuration fetched from the backend front-config API. This slice will be the single source of truth for dynamic routes in the application.

## Acceptance Criteria

**Given** the Redux store is configured
**When** the routes slice is created
**Then** it should:

- Store an array of route configuration objects
- Track loading state while fetching routes
- Track error state if fetching fails
- Provide initial empty state
- Include actions to set routes, set loading, and set errors

**Given** a route configuration response from the API
**When** the setRoutes action is dispatched
**Then** the routes should be stored in the Redux state

**Given** an error occurs while fetching routes
**When** the setError action is dispatched
**Then** the error message should be stored in state

## Technical Implementation

### State Shape

```typescript
interface RouteConfig {
  path: string;
  component: string;
  habitName: string;
  habitType: "complex" | "simple" | "withoutintervals";
  actionTypes: string[];
}

interface RoutesState {
  routes: RouteConfig[];
  isLoading: boolean;
  error: string | null;
}
```

### Required Actions

- `setRoutes(routes: RouteConfig[])`
- `setLoading(isLoading: boolean)`
- `setError(error: string | null)`
- `clearError()`

### Files to Create

- `front/src/redux/slices/routes/routes.ts` - Main slice
- `front/src/redux/slices/routes/routes.types.ts` - TypeScript types

### Files to Modify

- `front/src/redux/store.ts` - Add routes reducer

## Test Requirements (TDD - RED Phase)

### Unit Tests (`routes.test.ts`)

1. **Initial State Test**
   - Should have empty routes array
   - Should have isLoading as false
   - Should have error as null

2. **setRoutes Action Test**
   - Should store routes in state
   - Should clear loading state
   - Should clear any previous errors

3. **setLoading Action Test**
   - Should set loading state to true
   - Should set loading state to false

4. **setError Action Test**
   - Should store error message
   - Should set loading to false

5. **clearError Action Test**
   - Should set error to null

## Edge Cases

- Empty routes array from API
- Malformed route configuration
- Duplicate route paths
- Missing component names

## Validation Rules

- Routes array must be an array (even if empty)
- Each route must have: path, component, habitName, habitType
- Component name must be a non-empty string
- Path must start with '/'

## Integration Points

- Redux store configuration
- Future async actions for fetching routes
- App.tsx will consume this state
