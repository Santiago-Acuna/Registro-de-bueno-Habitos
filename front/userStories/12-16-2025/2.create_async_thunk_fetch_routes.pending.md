# US-002: Create Async Thunk for Fetching Routes

**Priority:** High
**Complexity:** Medium
**Estimated Time:** 2 hours
**Dependencies:** US-001

## User Story

As a frontend developer, I want an async thunk to fetch route configuration from the backend so that routes can be dynamically loaded when the application starts.

## Description

Create an async thunk using Redux Toolkit's `createAsyncThunk` to fetch route configuration from the backend front-config API endpoint. This will handle the API call, loading states, and error handling automatically.

## Acceptance Criteria

**Given** the application is starting up
**When** the fetchRoutes thunk is dispatched
**Then** it should:

- Set loading state to true
- Make GET request to `/api/v1/front-config/habits-by-type`
- Transform backend response into RouteConfig array
- Set loading state to false on completion
- Store routes in Redux state on success
- Store error message in Redux state on failure

**Given** the backend returns habits organized by type
**When** the response is received
**Then** routes should be generated with format:

- Path: `/{habitName}` (kebab-case)
- Component: Based on habitType (complex -> "ComplexHabits", simple -> "SimpleHabits", etc.)
- Include habitName, habitType, and actionTypes

**Given** the API request fails
**When** an error occurs
**Then** a user-friendly error message should be stored in state

## Technical Implementation

### API Response Structure

```typescript
{
  complex: [{ "Programming": ["for work", "personal Project"] }],
  simple: [{ "Morning Exercise": ["Cardio", "Strength"] }],
  withoutintervals: [{ "Water Intake": [] }]
}
```

### Route Generation Logic

```typescript
// Transform "Programming" -> "/programming"
// Transform "Learn English" -> "/learn-english"
// Map complexity to component:

//   simple -> "SimpleHabits"
//   withoutintervals -> "WithoutIntervalsHabits"
```

## Test Requirements (TDD - RED Phase)

### Unit Tests (`asyncActions.test.ts`)

1. **Successful Fetch Test**
   - Mock successful API response
   - Verify loading state transitions
   - Verify routes are stored correctly
   - Verify error is cleared

2. **Failed Fetch Test**
   - Mock API error response
   - Verify error is stored
   - Verify loading is set to false
   - Verify routes remain unchanged

3. **Network Error Test**
   - Mock network failure
   - Verify error message is user-friendly
   - Verify loading state is cleared

### Unit Tests (`routeMapper.test.ts`)

1. **Route Path Generation Test**
   - "Programming" -> "/programming"
   - "Learn English" -> "/learn-english"
   - Handle special characters
   - Handle spaces and dashes

2. **Component Mapping Test**
   - complex -> "ComplexHabits"
   - simple -> "SimpleHabits"
   - withoutintervals -> "WithoutIntervalsHabits"

3. **Action Types Test**
   - Should include action types array
   - Should handle empty action types

4. **Empty Response Test**
   - Should return empty array for no habits
   - Should not throw error

## Edge Cases

- Empty response from backend (all arrays empty)
- Network timeout
- 404 response
- 500 server error
- Malformed JSON response
- Duplicate habit names across different types
- Habit names with special characters (#, ?, &)

## Validation Rules

- API endpoint must be `/api/v1/front-config/habits-by-type`
- Response must have complex, simple, withoutintervals properties
- Generated paths must be URL-safe
- Component names must match actual component exports

## Integration Points

- Axios instance for HTTP requests
- Routes Redux slice
- Backend front-config controller
- Environment variables for API base URL
