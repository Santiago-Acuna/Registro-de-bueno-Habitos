# US-006: Add Route Error Boundary Component

**Priority:** Medium
**Complexity:** Small
**Estimated Time:** 1.5 hours
**Dependencies:** US-005

## User Story

As a user, I want graceful error handling when route components fail to render so that the entire application doesn't crash when a single route has an error.

## Description

Implement a React Error Boundary component to catch and handle errors that occur during route component rendering. This prevents the entire application from crashing if a single habit component encounters an error.

## Acceptance Criteria

**Given** a route component throws an error during rendering
**When** the error is thrown
**Then** the error boundary should:

- Catch the error before it crashes the app
- Display a user-friendly error message
- Provide option to navigate back to home
- Log error details to console for debugging
- Not affect other routes

**Given** an error is caught by the boundary
**When** the user navigates to a different route
**Then** the error boundary should reset and allow the new route to render

**Given** multiple errors occur in sequence
**When** each error is caught
**Then** each should be handled independently

## Notes

- Error boundaries don't catch errors in:
  - Event handlers (use try-catch)
  - Asynchronous code (use try-catch or .catch)
  - Server-side rendering
  - Errors in error boundary itself
- Consider adding error boundary to root route as well
- Consider per-route error tracking
- Future: Send errors to Sentry or similar service
- Follow React error boundary best practices
