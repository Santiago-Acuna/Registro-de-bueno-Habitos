# US-003: Create useRoutes Custom Hook

**Priority:** High
**Complexity:** Small
**Estimated Time:** 1.5 hours
**Dependencies:** US-001, US-002

## User Story

As a frontend developer, I want a custom hook to access routes state and actions so that components can easily fetch and consume route configuration without directly accessing Redux.

## Description

Create a custom React hook following the project's custom hooks pattern that encapsulates route-related Redux state and actions. This provides a clean API for components to interact with route configuration.

## Acceptance Criteria

**Given** a component needs access to route configuration
**When** it uses the useRoutes hook
**Then** it should receive:
- Current routes array
- Loading state
- Error state
- fetchRoutes function to trigger route loading
- clearError function to clear error messages

**Given** the hook is called multiple times in different components
**When** routes are fetched once
**Then** all components should receive the same state (single source of truth)

**Given** the fetchRoutes function is called
**When** the async operation completes
**Then** components should automatically re-render with new data

## Technical Implementation

### Hook API
```typescript
interface UseRoutesReturn {
  routes: RouteConfig[];
  isLoading: boolean;
  error: string | null;
  fetchRoutes: () => Promise<void>;
  clearError: () => void;
}

function useRoutes(): UseRoutesReturn
```

## Test Requirements (TDD - RED Phase)

### Unit Tests (`useRoutes.test.ts`)

1. **Initial State Test**
   - Should return empty routes array initially
   - Should return isLoading as false
   - Should return error as null

2. **Fetch Routes Test**
   - Should call fetchRoutes async thunk
   - Should update loading state during fetch
   - Should return routes after successful fetch

3. **Error Handling Test**
   - Should store error on failed fetch
   - Should set loading to false after error

4. **Clear Error Test**
   - Should clear error when clearError is called
   - Should not affect routes or loading state

5. **Stable References Test**
   - fetchRoutes function should have stable reference
   - clearError function should have stable reference
   - Should use useCallback for functions

6. **Multiple Hook Instances Test**
   - Multiple components using hook should share state
   - Update in one should reflect in all

## Edge Cases

- Hook called before routes are fetched
- Hook called during loading
- Hook called after error
- Multiple simultaneous fetchRoutes calls
- Component unmounts during fetch

## Implementation Guidelines

- Use `useAppSelector` for accessing state
- Use `useAppDispatch` for dispatching actions
- Use `useCallback` for fetchRoutes and clearError to ensure stable references
- Follow existing hook patterns (useBooks, useHabits)
- Include JSDoc documentation

## JSDoc Documentation Requirements

```typescript
/**
 * Custom hook for managing route configuration state.
 *
 * Provides access to dynamic routes fetched from the backend,
 * loading states, and error handling. Routes are cached in Redux
 * and shared across all components using this hook.
 *
 * @returns {UseRoutesReturn} Route state and actions
